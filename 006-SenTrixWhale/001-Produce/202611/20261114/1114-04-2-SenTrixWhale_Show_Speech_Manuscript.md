## 第 1 页 · SenTrixWhale：给家庭记忆助手装上 QQ 对话入口

这一页是本周进度的高强度概览，3 分钟左右讲完。左栏讲本工程的入口决策与四层链路，右栏是参照样本的实测记录。

先定位：SenTrixWhale 是依附组内记忆助手的对话分支，不另造记忆内核；记忆在既有内核，QQ 只是入口。这股 AI 人格化浪潮是切入时机。

入口取舍：B站是这股东风的来源，与产品形态不直接对接；QQ 协议端生态存续久、与形态最对接，是本轮主做方向；桌宠没有稳定协议端，作为未来方向观望；微信虽然人手一个，但个人号机器人封号风险高，本轮未采用。

右栏三组数字是参照样本（已上线那只鲸鱼）在云端 API 上的实测，10 月 20 号到 11 月 12 号：成本 12.78 元、日均 0.53 元、峰值 1.51 元/天；图像 135 张同源回归；单日最高 229 轮交互。用来说明这条路走得通，不代表本工程当前水平。

四层链路从上到下：第一层 QQ 接入，协议端收发消息；第二层桥接枢纽，收发去重、时间解析、相册路由、存图归档并写回 EXIF，另有超时兜底；第三层记忆与存储，多通道检索事件与时间线，图片落到地理目录；第四层本地模型，本地推理，对话不出机器。

内部注记（不进正文、口播不提）：桥接、记忆服务、本地模型所在机器号、端口、型号与参考工程名只在此掌握，本页正文不出现；协议端稳定性是内部准备项，临时桥的位置与形态不在本稿展开。家人鲸那套护栏是调云端 API 的费用保护；本工程接本地模型不产生 API 费用，桥接守护只指进程巡检、超时兜底和消息去重，不要讲成费用保护。
