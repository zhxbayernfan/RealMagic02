## 3. 卡点分析

### 3.1 Full run FTS缺失（当前核心瓶颈）

复用(run reuse)能拿1.1分，但full run（新建scope）得0.3分，因为新scope没有FTS关键词富化。

**修复方向**：把FTS关键词富化逻辑写进pipeline_processing阶段，让full run自动使用富化FTS。

### 3.2 Agent回答质量（次要瓶颈）

华哥分析1.1分run的第二题——Agent召回了正确照片但因干扰项答非所问。瓶颈从FTS检索转为Agent回答质量，后续可优化QA agent prompt/参数。

## 5. 经验总结

123部署过程中遇到的问题均为**配置/环境差异**，而非llama-server方案本身的缺陷：
1. 多处硬编码旧地址(153) → 已修
2. vLLM manager缺失 → 已改bind-runtime逻辑
3. bge sidecar(8101)未启动 → 已修复
4. FTS索引未自动构建 → **定向FTS富化完成(92条，1.1分)**

**核心发现**：定向FTS(92条)优于全量FTS(916条)——少而精准的关键词匹配远胜于大而全的噪音匹配。

**llama-server方案已验证可行**：管线22/22全通，QA评测1.1分超过118基线0.9。
