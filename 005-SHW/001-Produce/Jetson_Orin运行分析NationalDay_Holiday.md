## 五、143 MacMini M4部署方案

### 5.1 环境差异

| 项目 | 123 (AGX Orin) | 143 (MacMini M4) |
|------|----------------|------------------|
| 系统 | Linux ARM64 | macOS ARM64 |
| GPU | Orin集成GPU(2048 CUDA核, 统一内存) | Apple M4 (统一内存) |
| Python | 3.10 (conda) | 3.9 (系统) |
| CUDA | 12.6 | 无（Metal） |

### 5.2 部署步骤

1. **安装依赖**
   ```bash
   # Node.js（已安装v20.11.0）
   # Python依赖（需适配macOS）
   pip install -r backend/requirements.txt
   # 修改：onnxruntime-gpu → onnxruntime
   # 修改：transformers>=5 → transformers>=4.50
   ```

2. **配置本地推理**
   ```json
   {
     "sentrix_url": "http://127.0.0.1:11001",
     "model_base_url": "http://127.0.0.1:8100/v1"
   }
   ```

3. **复制模型到143本地**
   - Chinese-CLIP：从123复制（1.6GB）
   - VLM模型：从123复制qwen35-q4km.gguf（2.8GB）
   - 启动本地llama-server（需验证M4 Metal后端编译）

4. **运行测试**
   - 10QA快速验证
   - 100QA质量确认
   - 487QA最终验证

## 六、经验教训

### 6.1 成功因素

1. **单worker API**：解决turn内存共享问题
2. **纯chinese-clip索引**：统一检索向量空间
3. **top_k=40**：召回率与精准度最佳平衡
4. **及时清理**：磁盘/旧进程维护

### 6.2 踩坑记录

1. **多worker陷阱**：`_TURN_JOBS`是进程内内存，不共享
2. **向量混合**：buffalo_l(人脸)不能用于图像检索
3. **过度检索**：top_k过大引入噪声，降低质量
4. **视频NVDEC**：Jetson Orin需nvv4l2，非cuda

### 6.3 改进建议

1. **自动化检查**：部署前自动检测单worker/向量纯度
2. **质量门槛**：100QA>0.9再跑487QA
3. **视频处理**：适配nvv4l2或跳过视频
4. **文档完善**：部署清单+故障排查手册
