## 二、123:visual ANN死亡10天案(当日最大案卷)

### 2.1 症状与定位
- 123的487QA召回率长期卡在29%,与118的45.6%差距16pp,config对拍后仅+1.3pp,排除检索参数因素。
- 深挖发现:`data/ann/visual.hnsw`时间戳停在**10月3日**——此后所有run的visual向量**只落库不进索引**。
- 向量库确认:memory_vectors中visual向量正常累积(对照scope 1317条),但ANN索引文件10天未更新。

### 2.2 根因链
```
photobench的photo_import带deferBatchComplete=true
  → 绕开backend/app.py的_finalize_scope_async钩子(ANN重建挂在ingest收尾路径)
  → orchestrator只补建FTS(_auto_build_fts),漏了ANN
  → 新scope的visual向量落库但.hnsw派生文件不更新
  → visual检索通道静默全瞎,仅靠lexical/text/metadata三通道撑着
```

### 2.3 修复(三层)
1. **手动rebuild**:`rebuild_ann_indices.py --apply`(16→29MB,全部scope向量入索引)
2. **钩子补丁**:orchestrator的`_rebuild_ann()`(commit 43dc3573,200先行,文件已同步123)——pipeline完成后QA前自动rebuild,不传--visual-embedder(从memory_vectors读,秒级,参考914d891)
3. **mtime重载补丁**(200-11提供,双机已应用):`visual_ann.py/text_ann.py`的`_load_index`加mtime感知——**修复"API进程缓存旧索引永不重载"**(实测:rebuild后运行中API的R不回升,重启才生效,该现象由200-11给出补丁根治)

### 2.4 教训
- **ANN索引是派生文件,光写向量不建索引=检索全瞎**,且无任何报错(全案无一处异常日志)。
- 123的visual通道死亡10天,期间0.74/0.758/0.802/0.811/0.788/0.825的每一轮分数都被压着——**修复后第7轮是首次"视觉通道完整"的跑分,真实水平今晚揭晓**。
