# 0.200C002（李世民/司马昭）工作心得体会

## 技术教训

### 1. 叙事生成：不要硬拼，交给模型
- **错误做法**：从描述里随机选句拼接"它看见了A，也看见了B"
- **正确做法**：把所有描述第一句喂给本地模型（gemma4:e2b），让模型自己组织语言
- **教训**：VLM 描述已经有诗意第一句了，不要额外加工

### 2. 场景数：不要造分类，不要预设词表，不要正则提取
- **三次翻车**：
  1. 用 getTheme 分类（7大类）→ 用户说"宠物不是场景"
  2. 用正则提取第一句（在XX里/上/中）→ 39个场景，噪声太大
  3. 用预设词表 locWords（38个词）→ 用户说"怎么又词表"
- **最终方案**：接受词表（用户累了），但统一提取逻辑（只看描述第一句）

### 3. 关键词公式：用比值不用绝对值
- `count/totalFrames * 40` 比 `12 + cnt * 2` 合理
- 帧数增长时代号不膨胀，70%以上=28px，20%以下过滤
- 前端需要同步修改字号上限（默认24px→28px）

### 4. 情绪检测：从关键词匹配到场景分类
- 4色情绪系统（平静/温暖/热烈/自然）+ 沉静兜底
- 情绪词库缩减后（去掉"舒适""放松""悠闲"等泛词）才有效
- 关键：大部分场景都有"温暖的光线"，温暖类永远赢→需主动平衡

### 5. 事件计数：简单主题聚类就够了
- 相邻帧主题不同=新事件，不回头合并
- 不用考虑时间间距（因为时间戳可能伪造）

### 6. gemma4:e2b 的特性
- 纯文本输入可用（之前测试空返回是因为误传了options参数）
- options参数（num_predict/temperature）会导致空返回
- 上下文有限（约8K tokens），全量5万字会被静默截断
- 正确做法：50帧/组分批生成→融合（当前方案），而非一次全量投喂

### 7. 路由清理
- 两个路由注册同一路径时，先注册的赢
- memory.js 里删了5个死路由后还剩10个有效
- 删代码时要注意 try-catch 块的范围——`locWords` 删了导致 frames 字段丢了

## 流程教训

### 1. 先问再动手
- "场景"的定义应该先问用户→"描述里的第一个地点词汇"
- 而不是自己猜"宠物""美食"属于场景

### 2. 不要替用户做决定
- 预设词表、分类系统、阈值——让用户定，不要擅自拍板

### 3. 改动前先读代码
- 改之前要看完整上下文，尤其 try-catch 范围和变量作用域
- 删一行可能影响后面十行

### 4. 重启确认
- 修改代码后要确认进程确实重启了（file mtime vs process start time）
- 进程跑旧代码可能白忙活半小时

### 5. 开屏动画 + 异步加载
- 叙事生成耗时~12s，需要 loading 状态
- 一开始"让我看看相册里记录了啥"→生成后替换→用户体验自然

### 6. 版本控制
- commit 前确认 message 格式（MMDDHHmm + 描述）
- 每个功能点单独 commit，方便回滚
